# 晚风对话

面向 vivo WATCH GT 2（BlueOS / orbitV）的轻量恋爱对话小游戏。游戏没有文字输入框，玩家只通过大按钮选择行为。

## 玩法

- 启动后先阅读背景，然后选择“直接恋爱”或“追求他人”。
- 每天自动随机一个场景，共 10 个场景。
- 每天 10 轮，每轮提供 3 个行为选项。
- 聊天区保留最近 8 轮消息，并在每次选择后自动滚到最新一条。
- 自动保存角色、天数、场景、轮次、聊天记录和好感度，下次启动可继续游戏。
- 白天有 10% 的概率切换场景；成功切换后依次降为 8%、6%、4%、2%、0%。
- 夜晚根据事件进入电话陪伴、家里或酒店，10 轮后女方睡着，强制结束当天。

## 固定文本

游戏共有 70,000 条固定句子，运行时不生成新句子：

| 内容 | 句子数 |
|---|---:|
| 10 个白天场景 | 50,000 |
| 场景过渡语 | 100 |
| 夜间事件结果 | 50 |
| 酒店隐藏场景 | 2,000 |
| 三种态度池 | 16,800 |
| 高风险动作专属反应 | 1,050 |
| 合计 | 70,000 |

每个白天场景 5,000 句，由 30 个行为池（各 150 句）、500 条环境句和 10 条场景过渡语组成。

## 轻量化设计

- 不使用角色图、背景图或场景图，只保留应用图标。
- 主页面只包含界面、状态和游戏逻辑，不引用 70,000 句正文。
- 每个场景独立成加载页，只有选中该场景时才加载并解压一次。
- 高风险反应表单独异步加载一次，缓存为紧凑数组，主页面不再携带该数据。
- 每个场景先解压成普通数组；之后的每一轮都直接读数组，不再做 LZ 解压。
- 切换场景前释放上一场景对象，聊天界面最多保留最近 8 轮，只渲染当前需要的内容。
- 场景传递优先使用进程内缓存，并以 BlueOS 本地存储作为页面重建时的兜底。
- 主页面 JS 从约 1.2MB 降至约 24KB，具体安装包体积以 release 构建结果为准。

## 本地运行

安装依赖：

```bash
pnpm install
```

重新生成固定文本和压缩场景：

```bash
pnpm generate
```

检查完整的 70,000 句运行时数据：

```bash
pnpm audit
```

浏览器预览：

```bash
pnpm preview
```

然后访问 `http://127.0.0.1:8766/`。

## BlueOS Studio

1. 用 BlueOS Studio 导入本目录。
2. 安装依赖后启动“预览窗口”。
3. 在手表模拟器中检查界面和对话。
4. 使用 release / production 打包，将 `dist` 中的 `.rpk` 上传到 orbitV 或安装到手表。

## 数据校验

生成脚本会检查：

- 10 个场景各 5,000 句
- 酒店 2,000 句
- 夜间 50 句
- 过渡语 100 句
- 三种态度池 16,800 句
- 高风险动作反应 1,050 句
- 总计 70,000 句
- 全部句子不重复
- 好感语气统一使用“我 / 你”视角
- 室内场景不会混入晚风、街声或雨后路面
- 高风险动作分别使用与动作匹配的反应
